# KAI-89 Logical Data Models — Design Report (v1)

Status: DESIGN — pending critical review before bulk generation.
Date: 2026-08-14 · PR #174 · reconciled from ModelAgent A–E designs + AgentE calibration audit + owner-reviewed workbook.

## Model philosophy (all models)

Every derived value is one of:

- **A SOURCE-VERIFIED** — directly supported by official/authoritative evidence (ledger, workbook SOURCE_VERIFIED rows, editorial.fieldSources).
- **B CALCULATED** — deterministically derived from factual inputs (e.g. metres→minutes pace conversion, documented midpoint).
- **C MODEL ESTIMATE** — generated by a documented catalogue model over trusted peer records; confidence capped by calibration sample size.
- **D UNKNOWN** — insufficient information; stays unknown. Never coerced into ¥0/free/plausible numbers.

Invariants:

1. Override precedence: source-verified > calculated > high-confidence model > medium > low > unknown. Models NEVER overwrite stronger evidence (all KAI-89 ledger corrections are authoritative).
2. No arbitrary/template constants; no false precision (round to coarse increments: ¥100/¥500, minutes to 5, integer scores/bands).
3. Calibration ONLY on trusted records minus contamination exclusions; a model that recreates giant identical-value clusters has failed.
4. Every generated value carries provenance: `method`, `modelVersion`, `confidence`, `basis` (via editorial.fieldSources + EditorialRecord.modelMetadata; reuses existing conventions — SourceReference.type already includes "calculated").
5. Fallback hierarchies END in UNKNOWN; minimum sample sizes and maximum dispersion enforced per level.
6. Determinism: same input → same output; double-run byte-identical.

## Calibration truth (AgentE, adopted verbatim)

- Generic sample ladder: high ≥ 30 · medium ≥ 12 · low ≥ 5 · convention ≥ 3 · unknown < 3. Generic dispersion cap IQR/median ≤ 1.5.
- Validation — WHAT IS ACTUALLY IMPLEMENTED (not a proposal):
  - Deterministic calibration truth committed at `scripts/audit/kai-89-calibration-truth.json` (seed 20260814), trusted sets minus contamination exclusions; the catalogue itself is never truth.
  - Executable gates in `scripts/models/validate-models.ts` (wired into `npm run check:catalog-ci`): NaN/∞ rejection; min/max range bounds per field; out-of-range sanitization; giant-cluster guard (identical-output share caps); "tickets never modelled" membership check; budget midpoint invariant; per-field idempotence (double-run byte-identical); model-ownership scoping via the report's `touchedRecords`.
  - Model-internal controls: peer-cell medians with MIN_CELL_SAMPLES = 5 and dispersion cap IQR/median ≤ 1.5; confidence caps by cell size (n ≥ 30 → medium, ≥ 12 → low); hub tickets = 0 class convention; verified-ticket keep path.
  - The CV/LOO metric harness (MdAE, MAE, p90 error, signed bias, coverage-in-tolerance, cluster index, dispersion ratio) was a DESIGN PROPOSAL and is NOT implemented; this document no longer claims those metrics were measured. Claims of "calibrated on N trusted" below refer to manual calibration-set analysis (trusted minus exclusions), not cross-validated error metrics.
- Contamination exclusions (committed truth file `scripts/audit/kai-89-calibration-truth.json`):
  - ratings: 29/108 trusted are a formula template family (27 national parks with one identical offset profile + goryokaku/yoshinogari castle profile) → EXCLUDE from any rating/spend calibration.
  - visitDuration: same 12 parks at identical (2,5) → EXCLUDE.
  - bestMonths: 7 pipeline-default/all-12 + 8 suspect (3,4,10,11) inside season trusted → EXCLUDE from bestMonths truth.
  - walking: obi-castle walkingMin=5000 (metres in minute field) + 4 synthetic 60/40 sun/shade splits → EXCLUDE split values.
  - comfort: 5 impossible walkingIntensity values (12/20) → EXCLUDE (not clamp).
  - budget: trusted set has ZERO source-verified spend facts (Recommended is midpoint-formula on 76/78; components legacy) → spend calibration uses strict peer cells with capped confidence; tickets are the only class-A budget facts (~55 evidence facts: ledger 22 + workbook Sources 29 + fieldSources).
- Truth sources: trusted sets minus exclusions, PLUS corrections ledger, PLUS workbook NoBudget SOURCE_VERIFIED rows and Sources-sheet fees. The catalogue itself is never truth.

## 8. Migration strategy (all models)

1. `scripts/models/` — one versioned, deterministic, pure model file per field group (budget-model-v1.ts, season-model-v1.ts, duration-model-v1.ts, walking-model-v1.ts, comfort-model-v1.ts, crowd-model-v1.ts, transport-access-v1.ts) + `validate-models.ts` harness.
2. `npm run derive:destination-models` (generator): dry-run → `--apply`. Preserves source-verified values and manual overrides; fills only eligible unknown/template fields; NEVER overwrites higher-confidence data; emits a change/audit report. `--check` mode for CI staleness.
3. Overwrite ONLY the classes listed per model (templates, synthetic splits, unit-mismatched values, missing values with defensible model). KEEP: legitimate A clusters, KEEP_LOW_CONFIDENCE heuristics, 108 trusted records, corrections ledger, owner workbook PARTIAL_ACCEPT states.
4. Provenance: editorial.fieldSources (type calculated/official) + EditorialRecord.modelMetadata + seasonMetadata/transportMetadata.
5. Post-generation: regenerate detail files; run structured-cluster audit; compare old vs new distributions (giant-cluster detection); verify no 114-record vector reappears.
6. Runtime contract changes (walking sun badge/steps thresholds, MISSING_TRANSPORT_OPTIONS semantics) are separate P2 changes with equivalence tests; NOT bundled into the data generation.

## 9. Tests required (all models)

- Sanity/distribution gates in validate-models.ts (10 gates: NaN/Inf, min>max, out-of-range, giant-cluster with regression guards, deterministic same-input-same-output, unknown-reporting, held-out error metrics, tickets-never-modelled, midpoint invariant, contamination guard) wired into check:catalog-ci.
- Monotonic invariants where semantically valid: longer visits → not lower discretionary spend/walkingMin; higher indoorPercent → not worse rainFriendly; walkingMin ≤ visit-max×60; weekday ≤ weekend ≤ holiday (except metro-hub dip).
- Calibration reproducibility (seed fixed, fold ids committed).
- Unit tests per model + worked examples.

## 10. Self-review (critical) — reconciliation deltas applied

1. Budget confidence capped (Tier A → medium, Tier B → low) per AgentE; min≥tickets clamp added; hub tickets=0 labelled class convention.
2. Walking metre conversion restricted to real-distance metres only (template metres cleared, not converted) — prevents template laundering.
3. Comfort outliers excluded not clamped; 4 missed synthetic splits added to exclusions.
4. Transport source-verified count corrected to ~18–19; two-tier value bounds.
5. Ratings: no model is proposed for rating vectors (accepted confidence-gating work stays); the 29-record formula family is excluded from any calibration.
6. Season: neutralization-to-null is the primary action for hub templates (owner policy); indoor gets the explicit year-round marker rather than flat (7,7,7,7).
7. No model fills the 226 noBudget ranges or 208 noBudget tickets — they stay UNKNOWN per owner policy.

## 11. Self-review deltas (v1.1)

1. **Budget "deferred" class = returned to UNKNOWN.** The 219 template-budget records with unknown tickets have ALL budget fields (min/rec/max + breakdown) cleared to unknown — a partial budget without admission would be a misleading daily estimate. The model records them as eligible for a future ticket-verified fill. Net budget coverage: ~177 full model/verified vectors; the rest honest unknown (~46% of catalogue).
2. **Season nulling is a schema contract change (P1).** `season` is a REQUIRED field in the Destination type and MISSING_SEASON_DATA flags null for published non-hub records. Neutralizing ~250 template vectors to null requires: `season?` optional + `bestMonths?` optional in the type, the MISSING_SEASON_DATA rule adjusted (null-with-seasonMetadata-method-"unknown" is an explicit neutral state, not missing), scorer + SeasonalSuitabilityService verified null-safe (both already `?.` with fallback 5), audit/dispositions regeneration, warning-baseline update. This is the owner-sanctioned consequence of neutralizing templates — no false seasonal claims.
3. **Crowd has ZERO runtime/UI consumers** (verified: no non-test read of `crowd` anywhere). crowd-model-v1 output is therefore legacy-safe provenance: it replaces the fabricated template vectors with deterministic band values so any future display never shows template data, and provenance is recorded via editorial.fieldSources.crowd (method model). It is NOT a ranking/UI input.
4. Walking unit contract changes (sun badge `<3000` metre constant → indoorPercent/kind-derived level; getWalkingIntensity steps thresholds → minute bands) are separate P2 runtime changes with equivalence tests, not bundled into data generation.
