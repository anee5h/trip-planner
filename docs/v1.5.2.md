I think this is exactly the right next release. After v1.5.1, I wouldn't add more features—I would polish the experience. I'd rate this **9.8/10**.

There are just a few architectural tweaks I'd make.

---

# 1. Rename the release

I wouldn't call it:

```text
Visual Design System
```

because this release also fixes behavior (theme, preferences, state).

I'd use something like:

```text
v1.5.2 — Design System & UX Polish
```

or

```text
v1.5.2 — Product Polish
```

That better reflects the scope.

---

# 2. Don't implement theme in Settings

This is the only thing I'd change architecturally.

Your plan says:

```text
Settings.tsx

↓

toggle html.dark
```

I'd instead create a dedicated theme service.

```
ThemeProvider

↓

useTheme()

↓

Settings

Navbar Toggle (future)

System Theme

Everything else
```

Settings should **consume** the theme API, not own it.

That way you can later add:

- navbar theme toggle
- onboarding theme selection
- system listener
- keyboard shortcut

without duplicating logic.

---

### 3. Unified Base Location Single Source of Truth

- Replace the static Base Location text field in `Settings.tsx` with the reusable `StationInput` component used by the homepage.
- Establish a single source of truth for Base Location within the user preferences store. Homepage, Trip Planner, Search, Recommendation Engine, and travel-time calculations must all read from this shared preference.
- Remove inline Base Location editing from the homepage.
- Replace the homepage **Edit** button with **Change**, which navigates users to `/settings` and automatically opens the **General & Base Location** section.
- After saving a new Base Location, immediately update all dependent features and display a confirmation toast (e.g. _"Base Location updated to Shinjuku Station. Trip recommendations and travel times have been refreshed."_).

#### User Flow

```
Homepage
    ↓
📍 Base Location: Nakayama Station
[Change]

    ↓

/settings
General & Base Location

[ StationInput ]

Search stations...
```

```
Save Settings
    ↓
```

- Persist the updated Base Location to the user preferences store.
- Refresh Homepage recommendations and Trip Planner calculations automatically.
- Return the user to the previous page (or Homepage) with the updated Base Location displayed.

# Overall

I think you're entering a different phase of the project now.

Earlier versions were about **building capabilities**.

This release is about **making TabiMap feel intentional**.

If I were to reorder the priorities for v1.5.2, I'd do:

1. **Fix Base Location single source of truth** ⭐⭐⭐⭐⭐
2. **Fix Theme switching** ⭐⭐⭐⭐⭐
3. **Implement Data Export or disable it** ⭐⭐⭐⭐☆
4. **Standardize Lucide icons** ⭐⭐⭐⭐☆
5. **Profile hero redesign** ⭐⭐⭐⭐☆
6. **Command Palette spacing** ⭐⭐⭐☆☆
7. **Typography & spacing consistency** ⭐⭐⭐☆☆

The first three improve correctness. The rest improve polish. Together they'll make the product feel much more cohesive without introducing unnecessary complexity.
